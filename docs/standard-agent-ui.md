# 标准 Agent 输入、输出界面：评审与规范草案

范围：Toolkits Python SDK、对话模板、消息内容渲染、右侧详情、51 个 Agent 的静态声明。
本次为代码评审及规范定义，不表示下述目标均已实现，也未对 51 个 Agent 逐个完成真实推理测试。

## 结论

保留一个 SDK 和一个对话外壳，为内容类型定义标准展示，并显式区分四种使用位置：
输入编辑器、已提交输入消息、输出消息、详情面板。相同内容使用统一播放器／文本／表格基础组件；
编辑行为、摘要密度和辅助操作随使用位置变化，不能简单复用同一段 HTML。

本次静态扫描：51 个 Agent 均声明 Interface；47 个使用 Audio，40 个 Text，40 个 Table，17 个 Number，16 个 Select。
这些数字为使用该组件的项目数，不区分输入与输出，也不表示每个项目只有一个组件。
现有 SDK 还提供 AudioInfo，扫描到的正式 Agent 声明中没有直接使用它。

## 评审发现

1. 高优先级：多个内容块的身份会丢失。
   ui.css 对所有输入、输出消息的 .result > label 都设为隐藏。
   双音频比较、多个文字结果会失去“音频 A / B”“摘要 / 转录”等语义。
   应仅省略单一、含义明确的默认标题；多内容块必须保留标题与稳定标识。
2. 高优先级：自动提交依据输入形状推断，缺少业务所需的“准备完成”约束。
   Interface 当前对单音频且无附加音频／参考文本默认自动提交。
   submit() 仅统一检查 null/undefined，空文本可发送，尚无 required、长度及逐字段错误协议。
   需要可声明的校验；必填参数不全时保留素材并引导补全，不应静默开始或丢弃录音。
3. 中优先级：Table 承担了过多结果类型。
   ui-content.js 在消息中一律显示“n 条记录”。音频时间段、声纹分数、普通数据表无法体现主要结论。
   应明确普通表格、时间段、指标的语义，而不是按列名或 Agent 名称猜测布局。
4. 中优先级：详情面板只展示音频输入及输出。
   ui.js showDetail() 未展示原始文字输入和本轮参数快照。
   TTS、文字对话及多输入任务的详情不完整。详情必须从完整的轮次数据生成。
5. 中优先级：轮次状态还不是统一协议。
   当前完成结果存在 Map 中，渲染过程还直接操作 DOM；重试、处理中等状态没有完整的消息模型。
   当前页面没有持久化轮次存储；刷新会失去 SDK 对话历史。没有统一取消／流式追加接口。
6. 中优先级：录音编辑器缺少标准反馈。
   当前录音主要靠按钮形态变化；波形在录制结束、浏览器解码后绘制。
   应有录制时长、活动反馈、取消、权限错误，以及设备／浏览器能力说明。
7. 中优先级：视觉样式存在多次追加覆盖。
   ui.css 中卡片、消息、输入框规则重复覆盖；仍有大量固定浅色值。
   应收敛到统一尺寸、字体、颜色及间距 token，并验证深色、窄窗、键盘导航。

## 统一外壳

- 页面顶部：Agent 名称、必要说明、清空对话。
- 中间：顺序追加的轮次。输入消息靠右，回复靠左；一轮支持多个输入块和多个输出块。
- 底部：常驻编辑器。附加参数在编辑器上方，以胶囊展开编辑。多个主输入各自保留其附加参数。
- 右侧：用户点选结果后展示详情；默认关闭，关闭后恢复原会话位置。
- 内容相同但展示密度不同：消息展示主要内容，详情展示完整数据与操作。
- 参数是本轮输入的快照，不是回复结果。零、false 等有效值不得被当成空值隐藏。
- 后续轮次不会覆盖前一轮；失败重试更新原回复，不重复创建输入。

## 标准输入矩阵

| 输入类型 | 编辑区 | 输入消息 | 提交及状态 |
| --- | --- | --- | --- |
| 文字 | 自动增高的多行输入；长文本到上限后内部滚动 | 原始文字，保留换行；长内容可展开 | Enter 或发送按钮提交，Shift+Enter 换行；输入法确认候选词不提交；空必填输入禁发 |
| 单音频 | 一行：来源菜单、来源／录音状态、录音或停止按钮 | 文件名、时长、统一播放器；来源与时间可弱化展示 | 上传完成／停止录音后，全部必填参数满足才可自动提交；允许声明手动模式 |
| 多音频 | 每个主输入一个有标签的音频编辑器，附加项归属清晰 | 同一输入消息含多张有标签的音频卡片 | 全部必填音频就绪后统一提交；不自动逐个提交 |
| 参考音频及参考文本 | 音频胶囊打开一张编辑卡；文本附着于该音频 | 有标签的参考音频，参考文本可展开 | 未接入识别时说明需填写；有识别回调时先显示识别状态，允许校正 |
| 单选／多选 | 上方胶囊，弹层提供搜索、选中状态；多选明确完成操作 | 紧凑的“名称：显示值”，不展示内部 ID | 空选项、加载、失败、无匹配有明确状态；选择不直接触发运行 |
| 数字 | 上方胶囊，弹层数字输入／步进，显示范围、单位 | 小号“名称：数值＋单位” | 限制范围、精度及步长；错误在字段旁提示 |
| 表格 | 有标题的可编辑表格，支持增删行；较大表格展开编辑 | 行列摘要及查看入口 | 校验列与单元格；不把编辑表格铺满会话 |
| 布尔值（待补） | 胶囊弹层中的开关 | 明确“开启／关闭” | 使用独立布尔值，不以字符串或空值模拟 |

## 标准输出矩阵

| 输出类型 | 回复消息 | 右侧详情 | 标准操作 |
| --- | --- | --- | --- |
| 文字 | 直接展示主要文本；保留换行；长内容折叠 | 完整文本，关联本轮输入 | 复制、下载文本；Markdown 需明确格式并安全渲染 |
| 音频 | 统一播放器、时长；需要时显示输出标题 | 波形、播放进度、完整音频信息 | 播放暂停、定位、下载；输入和输出共用播放器 |
| 指标／分数 | 标签、值、单位，必要时显示已声明的结论 | 计算说明、完整指标、对应输入 | 复制／导出；不能所有数字都默认大字号 |
| 普通表格 | 列名和少量预览行、总行数 | 完整表格，滚动／分页 | 复制、CSV 下载；不只显示“n 条记录” |
| 时间段（待补） | 段数、总时长或简短转录摘要 | 时间轴＋分段列表，与来源音频关联 | 点击片段定位音频；可导出字幕；明确时间精度 |
| 音频信息 | 少量关键字段，如时长、采样率、声道 | 完整带显示名称和单位的属性表 | 复制／导出；内部字段不直接裸露 |
| 多内容输出 | 同一回复组合有标题的内容块，主要结果优先 | 本轮所有输入、参数及输出 | 各内容块独立操作，不拆成无关轮次 |
| 文件／图片／视频（后续扩展） | 按类型提供预览或附件卡 | 大图、播放器或完整文件信息 | 下载、展开；未知类型使用明确附件回退，不直接堆 JSON |

这里“时间段”“指标”是展示语义，不必各新增一套基础组件。
例如表格可声明 timeline 展示方式以及 start/end/text/音频来源字段映射；
数字可声明单位和显示精度。具体 Python 命名在实现前统一，不把这些草案当成已存在的 API。

## 最小协议

- Input：主组件、附加组件、必填及值约束、提交策略。
- Content：稳定 ID、类型、标题、值、显示元数据、可选来源关联。
- Message：角色、内容块列表、创建时间。
- Turn：ID、输入消息、回复消息、参数快照、状态、错误、关联素材。
- 状态：准备／运行／完成／失败／取消；流式内容属于同一回复的更新，不产生新轮次。
- 同一 Content 在 editor/message/detail 中使用同一类型注册表，但允许不同视图适配器。
- 不按模型名或 Agent ID 写界面分支；Agent 只声明内容及语义。
- 现有 tk.Text/Audio/Number/Select/Table、tk.Input 和字典分组写法保留兼容。
- 新字段需有 schema 版本、默认值及未知类型回退；更新 SDK 时应使旧 UI 定义缓存失效。

## 各场景验收

| 场景 | 必须验证 |
| --- | --- |
| ASR | 三种音频来源；输入播放器→转录回复；失败可重试；时间段能关联正确音频 |
| TTS | 多行输入及参数；文字→可播放音频；空文本禁发；流式 WAV 被正确规范化 |
| 文字对话 | 多轮追加；保留原输入；长回复可复制；如模型需要上下文，应有明确上下文传递协议 |
| S2S | 输入和输出播放器可区分；不得同时自动播放；来源关联正确 |
| 声纹比较 | A/B 标签始终可见；两段音频齐备再提交；分数及结论有单位／含义说明 |
| 会议纪要 | 一份音频对应转录、摘要、待办多个具名内容块；没有消息互相覆盖 |
| 参数编辑 | 单选、多选、空选项、数字边界、取消编辑及错误提示一致 |
| 全局 | 窄窗、深浅主题、键盘焦点、录音权限拒绝、断网、切换 Agent、清空及重试 |

以上是验收清单，并非已全部通过的测试结果。

## 实现次序

1. 先固定协议与状态，补必填／长度／范围约束、多个内容标签、参数与详情完整性。
2. 完成文字和音频输入／输出的组件样板页及交互测试，作为后续视觉基准。
3. 补选择、数字、表格、时间段和指标展示；用 ASR/TTS/声纹比较验证组合。
4. 收敛 CSS token、键盘与窄窗行为，再扩展流式回复、会话持久化及其它媒体。

避免继续逐个 Agent 修样式：同类型的问题必须在 SDK 的标准组件及回归用例里解决。
