# Releasing QwenAudio Toolkits

This project publishes application binaries through GitHub Releases. Model
weights, runtime archives, and the model catalog remain on ModelScope so the app
can download them independently of an application update.

## One-time GitHub setup

The repository needs these Actions secrets:

- `TAURI_SIGNING_PRIVATE_KEY`: the private key generated by the Tauri signer;
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: the password for that key, if one was
  configured.

The matching public key is committed in
`src-tauri/tauri.conf.json`. Never commit the private key, paste it into an
issue, or print it in an Actions log. Losing the private key prevents updates
to versions that already use its public key.

The release workflow runs on the Apple Silicon `macos-14` runner and builds the
DMG plus the signed updater bundle. It is defined in
`.github/workflows/release.yml`.

## Publish a version

1. Update the version in all package manifests:

   ```bash
   npm run version:set -- 0.1.0
   ```

2. Run the release checks locally:

   ```bash
   npm run lint
   npm test
   npm run build
   npm run open-source:check
   cargo fmt --manifest-path src-tauri/Cargo.toml --check
   cargo test --manifest-path src-tauri/Cargo.toml
   ```

3. Commit and push the version change, then push a matching tag:

   ```bash
   git tag v0.1.0
   git push origin v0.1.0
   ```

4. GitHub Actions creates a draft release and uploads the DMG, updater bundle,
   `.sig` signature, and `latest.json`. Review the draft assets and publish the
   release only after the DMG opens on a clean Apple Silicon macOS machine.

The workflow can also be started manually from the Actions tab by providing a
tag such as `v0.1.0`. Manual runs create the tag from the selected commit.

## Updater contract

Production builds use this static manifest endpoint:

```text
https://github.com/QwenAudio/qwen-audio-toolkits/releases/latest/download/latest.json
```

The manifest contains the latest semantic version, platform-specific updater
bundle URLs, and the signatures generated with the private key. The URLs and
signatures must belong to the same build. Do not replace an updater asset after
publishing a release without regenerating its signature and `latest.json`.

## macOS signing and notarization

The public preview currently uses ad-hoc signing and is not Apple-notarized.
Users may need to approve the first launch in **System Settings → Privacy &
Security**. Apple Developer signing and notarization can be added later with
the corresponding certificate and App Store Connect secrets; that is separate
from the Tauri updater signature.

## Release checklist

- [ ] Version, changelog, and user-facing documentation are updated.
- [ ] All required model sources, licenses, and checksums are public and valid.
- [ ] `npm run open-source:check` passes without private files or credentials.
- [ ] GitHub Actions has both Tauri signing secrets.
- [ ] Draft release contains a DMG, updater bundle, `.sig`, and `latest.json`.
- [ ] A clean-machine install and an update from the previous release succeed.
